# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

delegated: static HTML, CSS, and vanilla JavaScript so the site deploys directly from a GitHub Pages repository

## Users

Researchers, robotics and VLA engineers, prospective collaborators, and hiring teams who want to understand Zhangwei Chen's work quickly and verify the underlying code and evidence.

## Product Purpose

Present Zhangwei Chen as an early-career researcher working on robot simulation, embodied intelligence, and computer vision. The site should make his strongest project, VLA-Sync, legible within one viewport and provide direct paths to code, project evidence, notes, and contact.

## Positioning

The site is grounded in runtime reliability and evidence boundaries for VLA systems. It presents what was measured, where it was measured, and where the evidence stops.

## Operating Context

The site is a public GitHub Pages personal homepage. Visitors may arrive from a repository, a paper discussion, a research application, or a recruiting conversation. Most will scan on a laptop or phone before opening a project repository.

## Capabilities and Constraints

- Static assets and links must work on a user-level GitHub Pages domain.
- The page must distinguish simulation, offline replay, and real hardware evidence.
- Quantitative claims must come from the VLA-Sync repository or the supplied resume.
- No physical deployment, ROS integration, safety certification, or leaderboard result may be implied.
- The first release is a one-page site with anchor navigation and lightweight client-side interactions.

## Evidence on Hand

- `armbench-vla-runtime` / VLA-Sync, release v0.3.2, with checked-in project media and reports.
- Public projects `paperfield`, `ai-trade`, and `aimforge`.
- Resume facts covering Wuhan University, GPA, skills, honors, and project history.
- GitHub avatar and selected VLA-Sync poster and method landscape assets.

## Product Principles

- Lead with a falsifiable research focus.
- Put authentic project evidence before biography.
- Make artifacts one click away.
- State limitations beside the result they qualify.
- Keep the page calm, readable, and fast.

## Accessibility & Inclusion

Use semantic landmarks, visible keyboard focus, descriptive alt text, reduced-motion support, and layouts that remain readable at phone widths.
